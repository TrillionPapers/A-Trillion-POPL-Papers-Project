A regular expression describes a set of sequences: a language.

Edit, test, push is in it. So are three edits first. And so is no edit at all.

Your approval becomes a value in the program: a ticket.

The program gets it by asking. You see the plan, and you answer yes or no.

It cannot be copied.

And its type is the plan.

Every action replaces the plan by what is left of it.

After an edit, the whole plan is still there.

After the test, only the push remains.

After the push, the ticket is empty.

A second push is a type error, caught before the program ever runs.

A ticket for a plan also works for every smaller plan.

So doing less never needs a new question.

Doing more does. A push to another branch is outside the language, so the program must ask you again.

And the type checker knows which case you are in, before anything runs.

But you can lend it.

The helper takes the ticket, and must hand back a ticket for the same plan.

A helper that only edits can do that. A helper that runs the test cannot: its ticket has shrunk.

So when the ticket comes back, you know what the helper did not do, without reading its code.
