# What a rule on a command can promise

An agent harness decides from the text of a shell command whether a rule such as "allow `git diff`" covers it. The shell decides what runs from the text and from its surroundings: the values of variables, the names of the files in the directory, what other commands print. The bypasses of permission checks that were reported for coding agents in 2025 and 2026 live in this gap: a space hidden in `$IFS` ([Flatt Security, 2026](https://flatt.tech/research/posts/pwning-claude-code-in-8-different-ways)), a second command after a separator, a file named like a command, a line continuation inside a name. The idea is to make the question exact. A command is confined by a rule list if, in all surroundings an attacker can arrange, every program the shell starts and every argument it passes is allowed by the list. A paper would give a semantics of the part of the shell that agents use, tested against real shells; a checker that says "confined" only with a proof and "not confined" only with surroundings that show the break when they are replayed on a real shell; the line up to which the question can be decided (we expect that comparing strings brings in word equations, that string lengths bring in an open problem about them, and that the replacement operator of bash makes the question undecidable); and a machine-checked proof that the checker is sound for the semantics.

A first prototype (22 November 2026) speaks for the plan. A model of word expansion for a fragment was compared with dash, bash 3.2, and zsh in its sh mode on 60,000 random commands in random surroundings. It agrees with the real shells on all 204,440 runs that it predicts. The tests corrected the model in ten places on the way, and the points where the shells differ from each other are refused. On 6,000 random commands the checker settled 88 percent. All 2,711 breaks it reported were reproduced on the real shell, and no command it called confined was broken in 223,555 runs of the model and 15,104 runs of the real shells. One thing the tests found: `$x`, a backslash, a new line, and then `y` reads the variable `xy` in every shell we tried, so a line continuation can change which variable a command reads. The prototype does not yet cover a current bash, zsh in its native mode, redirections, or pipes, and its soundness has no written proof.

The closest work we found: Smoosh is an executable semantics of the POSIX shell, without an analysis ([Greenberg and Blatt, POPL 2020](https://doi.org/10.1145/3371111)). SaSh finds bugs in shell programs by optimistic symbolic execution and does not aim at an attacker ([Lazarek et al., SOSP 2026](https://doi.org/10.1145/3830418.3843861)). Studies of the permission lists of agents are empirical ([Chen and Lin, 2026](https://arxiv.org/abs/2606.15549); [Suwansathit, Zhang, and Gu, 2026](https://arxiv.org/abs/2603.27517)). Injection attacks were defined for query languages ([Su and Wassermann, POPL 2006](https://doi.org/10.1145/1111037.1111070); [Ray and Ligatti, POPL 2012](https://doi.org/10.1145/2103656.2103678)).
